# Quickstart: OpenUI AI-Generated Dashboard

**Feature**: 002-openui-ai-dashboard

---

## First-Time Setup

### Production / Portainer deployment

Images are pre-built by GitHub Actions and published to `ghcr.io`. Portainer pulls them
automatically when the stack is deployed or when the GHA webhook fires. No local build required.

```bash
# 1. In Portainer, deploy the stack using docker-compose.yml from the repository.
#    Portainer will pull all ghcr.io images automatically.
#    Ollama will auto-pull qwen2.5:7b on first container start (~5 GB download).

# 2. Monitor Ollama model pull progress
docker logs -f burndown_ollama

# 3. When you see "model pulled successfully", the AI dashboard is ready.
#    Open the app and click the "AI Dashboard" toggle in the nav bar.
```

To push a new deployment: merge to `master`. GitHub Actions builds, pushes to `ghcr.io`,
and calls the Portainer webhook automatically. No manual steps required.

### Local development (build from source)

```bash
# Use the dev overlay to restore build contexts
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build

# Monitor Ollama model pull progress
docker logs -f burndown_ollama
```

## Editing the Dashboard Declaration

The declaration file controls what the AI generates. There are two ways to update it:

### Option A — API (no rebuild, change persists across restarts)

```bash
curl -X PUT http://localhost:6088/api/ai-dashboard/declaration \
  -H 'Content-Type: application/json' \
  -d '{"content": "Show all in_progress projects ordered by budget consumed (highest first).\nFor each project show a ProjectCard followed by a BurndownChart.\nStatus thresholds: at-risk >= 70%, over-budget > 100%."}'
```

The change takes effect on the next dashboard load (cache is cleared automatically).

### Option B — Bake into image via GHA (edit the source file)

```bash
# Edit the declaration in the repository
nano api/dashboard.declaration.md   # or your preferred editor

# Commit and push to master — GitHub Actions rebuilds the api image and
# triggers the Portainer webhook automatically. No manual docker build needed.
git add api/dashboard.declaration.md && git commit -m "chore: update dashboard declaration"
git push origin master
```

**Example declarations**:

```
# Simple — show all in_progress projects
Show all in_progress projects ordered by budget consumed (highest first).
For each project show a ProjectCard followed by a BurndownChart.
```

```
# Custom thresholds
Show all in_progress projects ordered by budget consumed (highest first).
For each project show a ProjectCard followed by a BurndownChart.
Status thresholds: at-risk >= 70%, over-budget > 100%.
```

Reload the AI dashboard after updating — the layout reflects the new declaration.

## Adding a New openUI Component

1. Create the React component in `frontend/src/components/ai/MyComponent.ai.jsx`
2. Define its schema and register it in `frontend/src/components/ai/components.js` (follow the existing `ProjectCardDef` / `BurndownChartDef` pattern)
3. Validate locally: `docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build frontend`
4. Commit and push to `master` — GHA rebuilds the frontend image and triggers Portainer redeploy.
5. Update `api/dashboard.declaration.md` (or use the `PUT` endpoint) to reference the new component by name.

The system prompt in `api/src/services/ai-dashboard.js` also needs updating to tell the model about the new component and its positional argument order.

## Checking AI Service Status

```bash
# Check Ollama availability and cache state
curl http://localhost:6088/api/ai-dashboard/status
# {"ollama":"ready","model":"qwen2.5:7b","cached":false}

# View current parsed thresholds from declaration
curl http://localhost:6088/api/ai-dashboard/config
# {"thresholds":{"atRisk":80,"overBudget":100}}

# Full diagnostic (declaration, projects, Ollama test)
curl http://localhost:6088/api/ai-dashboard/debug

# Force cache invalidation — update the declaration (even a no-op update works)
curl -X PUT http://localhost:6088/api/ai-dashboard/declaration \
  -H 'Content-Type: application/json' \
  -d "$(jq -n --rawfile c api/dashboard.declaration.md '{content: $c}')"
```

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| Toggle shows "AI unavailable" | Ollama not running or still pulling | `docker logs burndown_ollama` |
| AI dashboard loads slowly every time | Cache not working | Check `GET /api/ai-dashboard/status` for `"cached": true` |
| Components not rendering | Unknown component name in model output | Only `Dashboard`, `ProjectCard`, `BurndownChart` may be generated by the model |
| First-time pull hangs | No internet access on host | Pull manually: `docker exec burndown_ollama ollama pull qwen2.5:7b` |
| Dock/browser shows wrong icon | Browser cache | Hard refresh (`Cmd+Shift+R`) or clear site data |
| AI dashboard blank on page load; appears after manual reload | localStorage-restore path not triggering stream on mount | Ensure `AIDashboard` reads `burndown_dashboard_mode` from localStorage in its mount effect and initiates streaming immediately, identical to a toggle click |
| AI dashboard shows "generation seems stuck" after partial content | Stall detected: no token for 15 s mid-stream | Check Ollama container resources (`docker stats burndown_ollama`); click retry — stall prompt keeps partial layout visible |
| AI dashboard shows error after streaming appeared to complete | Stream closed without `[DONE]` sentinel | Backend did not emit the end-of-stream sentinel; check API logs for premature SSE close |

## Sharing Ollama with Monatsabschluss

If the Monatsabschluss project also runs an Ollama container on the same host,
configure both stacks to use a **shared external Ollama container** to avoid
duplicate model downloads and memory usage:

1. Run a single Ollama container on the host (outside both Compose stacks).
2. In both `docker-compose.yml` files, set `OLLAMA_URL` to point to the shared
   Ollama container's address (e.g., `http://host-gateway:11434`).
3. Remove the `ollama` service from both Compose files.
